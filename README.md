# SUNKORA ROLEPLAY

Игровой RP-проект на основе SA-MP / open.mp. В этом репозитории сейчас
находятся **сайт**, **форум**, **Wiki** и **оформление**.

## Состав репозитория

| Каталог | Содержимое |
|---|---|
| `Сайт/` | Публичный сайт и личный кабинет (PHP) |
| `Форум/` | Форум сообщества (PHP) |
| `Вики/` | База знаний (PHP) |
| `Оформление/` | Фирменная графика |
| `server/` | Планируемое расположение исходников Pawn (пока не загружены) |

**Статус игрового мода: не собран и не протестирован.** Старые архивы
v0.10-dev сами по себе не подтверждают работоспособность игрового сервера.

## Установка сайта, форума и Wiki

Для каждого компонента нужен хостинг с PHP 8.1+; приложения устанавливаются
в отдельные корни сайтов или поддомены.

Сначала настройте на стороне хостинга **три разных секретных ключа установки**
(32–90 символов):

- `SUNKORA_SITE_INSTALL_KEY`
- `SUNKORA_FORUM_INSTALL_KEY`
- `SUNKORA_WIKI_INSTALL_KEY`

Генерируйте каждый ключ отдельно: `openssl rand -hex 32`. Передавайте
переменные через настройки PHP-FPM, Apache virtual host или окружение
контейнера, **не через публичный GitHub**. После настройки PHP откройте
страницу установки соответствующего компонента и введите выданный ключ.
Для каждого сайта настройте права записи на собственную папку данных.

Ранее ключи находились в истории репозитория — **обязательно используйте
новые значения**. Подробнее: [SECURITY.md](SECURITY.md).

## Автоматические проверки

- `.github/workflows/php-checks.yml` — PHP lint и проверка, что установка
  невозможна без переменных окружения.
- `.github/workflows/pawn-build.yml` — отдельная сборка Pawn через официальный
  компилятор после загрузки разрешённых к распространению исходников в
  `server/`. Пока исходников нет, workflow выдаёт явную ошибку.

### Подготовка server/ для собственного мода

Внутри `server/` должны быть: `gamemodes/sunkora.pwn`,
`filterscripts/other.pwn`, `pawno/include/`, `BUILD-LINUX.sh` и остальные
необходимые файлы сборки. Не загружайте чужие токены, базы аккаунтов,
логи, исполняемые файлы неизвестного происхождения и ресурсы без права
на распространение.

Для последующей проверки в Actions откройте **Pawn Compile** →
**Run workflow**. Полученный `.amx` ещё необходимо проверять на тестовом
сервере с MySQL и клиентом.

## Данные и безопасность хостинга

По умолчанию Wiki хранит статьи и учётную запись администратора в
`Вики/storage/wiki.json`. Для Apache 2.4 добавлены правила запрета
прямых HTTP-запросов к служебным каталогам сайта, форума и Wiki.
Nginx требует отдельной настройки — см. [SECURITY.md](SECURITY.md).

При желании Wiki можно перевести на `SUNKORA_WIKI_STORAGE_DIR`
вне публичного каталога. Для уже установленного проекта сначала
перенесите существующие файлы хранилища и лишь затем установите
переменную окружения. GitHub Actions выполняет проверку маршрутов
хранения и сохранения тестовых данных.
